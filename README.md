# wargether

전쟁으로 일상이 바뀐 사람들이 **학습 + 여가** 모임에서 관계를 이어 가는 서비스입니다. React 프런트엔드, Cloudflare Workers API 서버, 영구 D1 데이터베이스로 구성됩니다. 브라우저 localStorage 스냅샷을 신뢰하던 이전 버전을 대체합니다.

## 구조

```text
frontend/        React 화면, 대화상자, 클라이언트 타입
backend/         서버 권한·검증·모임·안부·신고·기관 전달 로직
backend/test/    SQLite 기반 다중 계정 통합 테스트
app/             페이지와 API 라우트 연결, ChatGPT 인증 어댑터
worker/          Cloudflare 서버 진입점
db/             Drizzle 데이터 모델
drizzle/        버전 관리하는 SQL 마이그레이션
public/          정적 아이콘·일러스트
scripts/         설치·빌드·런타임 도구
```

화면과 서버 코드는 분리되어 있고, `/api` 요청은 서버에서 처리합니다. 운영은 동일 출처 URL을 사용하므로 API 키를 브라우저에 넣거나 넓은 CORS 허용을 설정할 필요가 없습니다. 정적 화면만 호스팅하는 프로젝트가 아닙니다. Node VM이나 별도 VPS가 필요한 구성은 아닙니다.

## 실제 기능

- ChatGPT 계정 인증 → 닉네임·멘토/멘티 프로필. 계정별 데이터와 권한 검증.
- 두 활동이 필수인 모임 생성, 정원에 맞춘 원자적 참여 처리, 나가기, 저장, 모임 종료.
- Zoom / Discord / 카카오 오픈채팅의 HTTPS 링크 검증. 링크는 참여자에게만 공개.
- 모임 게시판: 영구 저장, 재전송 중복 방지, 최근 글 100개 표시. 같은 탭의 초안만 sessionStorage에 보관.
- 일정, 사전 불참 안내, 모임장 출석 관리, 참여자 주제 제안·투표·모임장 반영.
- 안내 없는 불참 3회 이후 안부 확인 요청. 사전 안내·통신 장애·취소 일정·가입 전 일정 제외.
- 서로 다른 현재 참여자의 안부 요청 3개 → 영구 기관 전달 큐. 중복 요청은 한 번만 집계.
- 기관 전달은 본인의 연락처 공유 동의와 실제 수신 채널이 모두 있어야 실행.
- 부적절한 행동 신고는 안부 확인과 분리. 대상자를 제외한 현재 활성 참여자에 모임장을 포함하고, **절반을 초과**한 신고가 있어야 모임장이 검토 사유를 남겨 참여 제한.
- 탈퇴한 신고자는 집계에서 제외. 제한·해제는 감사 기록 보존. 해제 후 자동 가입하지 않고 정원에 맞춰 본인이 재참여.
- 모임 소식 알림, 읽음 처리. 종료된 모임도 참여자의 나의 모임에서 확인.

## 인증 경계

`app/chatgpt-auth.ts`는 Sites의 인증 게이트가 전달하는 검증된 사용자 ID를 읽습니다. 브라우저가 보낸 사용자 ID나 역할을 권한 근거로 사용하지 않습니다. 계정은 서로 다른 실제 로그인이어야 합니다. 모든 쓰기는 같은 출처의 JSON 요청만 허용하고 서버에서 필드·멤버십·소유권을 검증합니다.

**이 서버를 검증 헤더를 제거하지 않는 임의의 프록시 뒤에 그대로 공개하지 마세요.** 다른 호스팅으로 옮길 때는 검증된 세션/JWT 인증 어댑터로 교체해야 합니다. `backend/service.mjs`의 `userId`는 신뢰할 수 있는 서버 인증 결과를 받는 인터페이스입니다. 테스트용 계정 전환/로그인 우회 API는 배포 코드에 없습니다.

## 설치와 검증

Node 22.13 이상(테스트의 `node:sqlite` 지원 버전)이 필요합니다.

```bash
npm run install:ci
npm test
npm run typecheck
npm run build
```

D1 모델 수정 후 `npm run db:generate`로 SQL과 메타데이터를 함께 커밋합니다. 이미 적용된 마이그레이션은 수정하지 않습니다. 로컬 DB 초기화는 빌드 후:

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_modern_tombstone.sql
npm run dev
```

로컬 미리보기 데이터는 운영 데이터와 다릅니다. 배포 시 `.openai/hosting.json`의 `DB` 바인딩에 영구 데이터베이스를 연결하고 `drizzle/` 마이그레이션을 적용합니다. 생성된 `dist/`, `.wrangler/`, 환경 파일, 테스트 DB는 커밋하지 않습니다.

## 구호기관 수신 채널

기관과 합의한 접수 시스템을 연결할 때 운영 서버 환경 변수에 다음 두 값을 설정합니다. 실제 수신처가 지정되지 않은 초기 배포에서는 외부로 전송하지 않고 `기관 연결 대기`로 남습니다.

| 변수                | 값                                  |
| ------------------- | ----------------------------------- |
| `AID_WEBHOOK_URL`   | 기관이 승인한 HTTPS 접수 엔드포인트 |
| `AID_WEBHOOK_TOKEN` | 기관과 합의한 Bearer 인증 토큰      |

기관 데이터 형식은 `backend/outbox.mjs`에 있습니다. 전달 항목은 요청 식별자, 닉네임, 본인이 입력한 연락처와 지역, 안부 요청 수, 생성 시각입니다. 신고 사유와 게시판 내용은 보내지 않습니다.

`Idempotency-Key` 헤더는 동일 사건의 재시도마다 유지됩니다. 수신 기관 역시 이 키로 중복 접수를 차단해야 합니다. 전송의 정확히 한 번 실행을 네트워크만으로 보장할 수는 없습니다. 응답이 2xx인 경우에만 `delivered`가 됩니다. 이는 기관 서버 전달 성공이며 구조/현장 확인 완료가 아닙니다.

세 번째 안부 요청 시 첫 전달을 시도합니다. 실패하면 큐에 남기고, 모임장의 **전달 다시 확인**으로 재시도할 수 있습니다. 코드의 `drainOutbox`는 별도 스케줄러에서 호출할 수 있도록 분리되어 있지만, 현재 배포에는 무인 주기 실행기가 연결되어 있지 않습니다. 그러므로 브라우저가 닫힌 상태에서 자동 재시도가 보장된다고 표시하지 않습니다. 운영 연계 시 기관의 재시도·접수 확인·보존 기간·연락 담당자를 함께 정해야 합니다.

## 확인한 테스트 범위

실제 SQLite 스키마에서 별개의 계정으로 인증 부재, 출처 위조, 정원 동시 참여, 메시지 재전송, 출석 제외 조건, 중복 안부 요청, 사건 종결, 과반수 재검증, 접근 제한·복구, 연락 동의, 전달 실패·재시도·중복 방지, 주제 투표를 검증합니다. 실제 기관에 테스트 메시지를 보내지 않습니다.

## 운영 상태와 한계

- 현재 사이트의 공개 범위는 소유자 전용입니다. 실제 여러 참여자를 받으려면 사이트 접근 권한을 초대 또는 공개 범위로 별도 설정해야 합니다. 앱의 계정별 권한 검사는 그대로 적용됩니다.
- 로그인 수단은 ChatGPT 계정입니다. 독립 이메일/비밀번호 인증은 포함하지 않습니다.
- 기관 주소·토큰이 없으면 기관 연락은 활성화되지 않습니다. 메일이나 SMS 발송도 자동으로 가정하지 않습니다.
- 현재 200개 모임, 50개 일정, 최근 게시글·제안·안부 사건 100개를 화면에 표시합니다. 데이터 자체는 영구 보관됩니다. 대규모 운영 전 페이지네이션과 보존/삭제 정책이 필요합니다.
- 긴급 구조나 위험 판정 시스템이 아닙니다. 통신 단절을 위험으로 확정하지 않습니다. 외부 영상 통화는 연결 가능한 지역에서만 선택적으로 사용하고, 텍스트 게시판을 병행합니다.

기존 프로토타입의 브라우저별 임시 계정·가상 모임은 실제 계정 소유권을 검증할 수 없어 운영 DB로 자동 이관하지 않습니다. 이전 코드는 Git 이력에 남습니다.
