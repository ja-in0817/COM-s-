# 모아 독립 서버 배포 안내

이 문서는 자체 로그인과 SQLite를 사용하는 모아를 외부 서버에 배포하는 절차입니다. 배포 설정 파일을 준비한 것과 실제 공개 서버를 생성한 것은 다릅니다. **현재 제공물에는 호스팅 계정에서 생성·확인한 공개 운영 URL이 포함되어 있지 않습니다.** 지속 운영할 서버를 만들려면 소유자의 호스팅 계정 연결과 해당 요금제 선택이 필요합니다. 로컬 실행은 README를 참고하세요.

## 배포 구조

React 화면을 빌드한 결과와 Node.js 24 API 서버를 하나의 컨테이너에서 실행합니다. 회원·세션·모임·대화·신고·연결 요청은 SQLite에 저장합니다. 데이터베이스 파일을 영속 디스크에 두고 **인스턴스는 하나만** 실행합니다. 이번 구성에는 PostgreSQL이 필요하지 않습니다.

| 항목 | 설정 |
| --- | --- |
| 시작 명령 | `npm start` |
| 런타임 | Node.js 24 |
| 공개 주소 | HTTPS인 실제 서비스 주소 |
| 상태 확인 | `GET /api/health` |
| 컨테이너 데이터베이스 | `/app/data/moa.sqlite` |
| 영속 디스크 마운트 | `/app/data` |
| 인스턴스 수 | 1 |

`/app/data` 아래의 SQLite 본체와 동반 파일을 함께 보존해야 합니다. 컨테이너를 다시 만들 때 데이터 볼륨까지 삭제하면 회원과 대화도 사라집니다. 업로드한 사용자 데이터와 백업은 저장소에 포함하지 않습니다.

## 환경 변수

| 이름 | 용도와 설정 |
| --- | --- |
| `NODE_ENV` | 운영 환경은 `production` |
| `PORT` | 호스팅 제공자가 지정하는 수신 포트. 직접 운영할 때 기본 3000 |
| `APP_ORIGIN` | 브라우저에서 접속할 정확한 HTTPS 출처. 경로·쿼리 없이 입력. Render의 기본 주소를 사용할 때 생략하면 `RENDER_EXTERNAL_URL`을 사용 |
| `DATABASE_PATH` | 운영 환경은 `/app/data/moa.sqlite` |
| `TRUST_RENDER_PROXY` | Render 공개 웹서비스에서만 `1`. 제공한 Render 설정에 포함되어 있으며 아래 `RENDER=true`와 함께 있어야 동작 |
| `RENDER` | Render가 자동 제공하는 `true`. 다른 호스트에서 이 값을 만들어 Render 신뢰 모드를 켜지 않음 |
| `TRUSTED_PROXY_IP` | 다른 호스트에서 선택적으로 사용하는 프록시의 정확한 단일 IP. 목록·대역·와일드카드는 허용하지 않음 |
| `INITIAL_ADMIN_USERNAME` | 선택 사항. 활성 운영자가 없는 첫 시작에 생성할 아이디 |
| `INITIAL_ADMIN_PASSWORD` | 선택 사항. 최초 운영자 비밀번호. 12~128자이며 비밀 환경 변수로만 설정 |

운영 환경에서는 HTTPS `APP_ORIGIN`과 Secure 쿠키를 강제합니다. 앱이 `http://` 주소로 구동되지 않도록 검증하는 것이므로 TLS는 호스팅 제공자 또는 앞단 프록시에서 처리해야 합니다. 프록시가 사용자의 임의 헤더를 운영자 신원으로 전달하도록 구성하지 마세요. 인증은 앱의 세션 쿠키로만 결정합니다.

접속 횟수 제한에 사용할 IP는 기본적으로 직접 연결한 주소이며, 임의의 `X-Forwarded-For`, `CF-Connecting-IP`, `X-Real-IP`는 무시합니다. Render 공개 웹서비스에서는 `TRUST_RENDER_PROXY=1`과 Render가 자동 제공하는 `RENDER=true`가 모두 있을 때만 유효한 단일 `CF-Connecting-IP`를 사용합니다. Render는 공개 웹서비스의 해당 헤더를 방문자가 보낸 값 대신 실제 접속 IP로 덮어쓴다고 [공식 안내](https://render.com/articles/host-pocketbase-on-render)에 명시하며, 자동 환경 변수는 [공식 환경 변수 문서](https://render.com/docs/environment-variables)에서 확인할 수 있습니다. 다른 호스트에서는 `TRUSTED_PROXY_IP`에 실제 앞단 프록시의 정확한 IP를 지정하고, 그 프록시가 방문자가 보낸 `X-Real-IP`를 신뢰할 수 있는 접속 IP로 항상 덮어쓰도록 구성합니다. 앱에 직접 연결한 주소가 설정한 프록시 IP와 일치할 때만 유효한 단일 `X-Real-IP`를 사용하며, 쉼표로 이어진 주소 목록이나 잘못된 값은 거절합니다. 어느 모드에서도 임의의 `X-Forwarded-For`로 접속 제한 주소나 회원 신원을 바꿀 수 없습니다.

최초 운영자를 만든 뒤 `INITIAL_ADMIN_PASSWORD`와 `INITIAL_ADMIN_USERNAME`을 호스팅 환경 변수에서 제거합니다. 비밀번호는 데이터베이스에 해시로 저장되며 다음 시작 때 기본 계정을 다시 만들지 않습니다. 새 비밀번호가 필요하면 관리 CLI로 재설정합니다.

## Render에 배포하기

Render의 공개 웹서비스와 유료 영속 디스크를 사용하는 방법입니다. 2026년 11월 18일 공식 문서 확인 기준으로 무료 웹서비스에는 영속 디스크를 연결할 수 없습니다. SQLite 데이터를 유지해야 하는 이 앱은 무료 웹서비스만으로 배포하면 안 됩니다.

1. 소유자의 Render 계정에 로그인하고 이 코드가 있는 GitHub 저장소를 연결합니다. 저장소가 비공개라면 해당 저장소를 읽을 권한을 부여합니다.
2. 저장소 루트의 `render.yaml`을 사용합니다. 설정 파일은 저장소 루트 기준으로 `./standalone/Dockerfile`과 `./standalone` 빌드 컨텍스트를 사용합니다. 서비스·영속 디스크 설정과 실제 저장소 경로가 일치하는지 검토합니다.
3. 요금제와 디스크 용량을 확인합니다. 서비스는 하나, 영속 디스크는 `/app/data`에 연결합니다.
4. `DATABASE_PATH=/app/data/moa.sqlite`, `NODE_ENV=production`은 설정 파일에 포함되어 있습니다. 기본 `onrender.com` 주소는 Render가 제공하는 `RENDER_EXTERNAL_URL`로 자동 설정됩니다. 별도 도메인을 사용하면 `APP_ORIGIN`에 그 HTTPS 주소를 지정합니다. 최초 운영자 아이디와 비밀번호는 생성 화면의 환경 변수 입력란에 입력합니다.
5. 빌드와 시작 로그를 확인하고 `/api/health`가 `ok: true`를 반환하는지 확인합니다.
6. 공개 주소에서 운영자로 로그인하고 초대코드 발급·참여자 가입·모임·메시지 저장을 확인합니다. 재시작 후 같은 데이터가 유지되는지도 확인합니다.
7. 최초 운영자 환경 변수를 제거하고 재배포합니다. 아래 백업 절차와 운영자 연락 방법을 준비한 뒤 실제 참여자에게 주소를 안내합니다.

공개 주소가 바뀌거나 사용자 도메인을 연결하면 `APP_ORIGIN`도 새 주소로 갱신해야 합니다. 이름이 다른 두 주소를 번갈아 쓰지 말고 한 주소를 기준으로 안내하세요.

**영속 디스크의 제한:** 디스크는 실행 중인 서비스에 연결되므로 빌드 단계, pre-deploy 작업, 별도 one-off 작업에서 데이터베이스를 초기화하지 않습니다. 이 앱은 실행 시 데이터베이스를 준비합니다. 디스크를 연결한 Render 서비스는 여러 인스턴스로 확장할 수 없고 재배포 때 짧은 중단이 발생할 수 있습니다.

확인한 공식 문서:

- [Render Docker 배포](https://render.com/docs/docker)
- [Render 영속 디스크](https://render.com/docs/disks)
- [Render 웹서비스](https://render.com/docs/web-services)
- [Render Blueprint 설정](https://render.com/docs/blueprint-spec)
- [Render 요금](https://render.com/pricing)

요금은 제공자의 실제 생성 화면을 최종 기준으로 확인합니다. 이 문서의 작성·설정 파일 제공만으로 서비스 구매나 과금이 발생하지 않습니다.

## 다른 서버와 Docker

Docker를 사용할 때는 제공한 Dockerfile로 앱을 빌드하고, 영속 볼륨을 `/app/data`에 연결합니다. 환경 변수는 위 표와 동일하게 설정합니다. 서버 앞단에서 HTTPS를 제공하고 앱이 받은 포트로 요청을 전달합니다. 데이터 디렉터리는 컨테이너 사용자에게 쓰기 권한이 있어야 합니다.

`compose.yaml`을 사용하는 로컬 확인에서는 `NODE_ENV=development`와 브라우저의 로컬 주소를 사용합니다. 공개 운영 환경에서는 `NODE_ENV=production`으로 전환하고 실제 HTTPS 주소를 설정해야 합니다. `docker compose down -v`처럼 볼륨을 함께 삭제하는 명령은 운영 데이터를 삭제하므로 배포·재시작 명령으로 사용하지 않습니다.

Railway 등의 다른 호스팅으로 옮길 때도 영속 볼륨, 한 인스턴스, HTTPS, 실제 `APP_ORIGIN` 조건을 유지해야 합니다. 임시 체험 VM이나 만료되는 무료 크레딧을 장기 운영 계획으로 간주하지 마세요.

## 운영자 계정 관리

관리 CLI는 **실제 데이터베이스가 연결된 환경**에서 실행해야 합니다. 운영 서버와 무관한 로컬 DB에 계정을 만들어도 운영 서버의 로그인 계정은 생기지 않습니다. Render에서는 디스크가 연결된 실행 서비스의 Shell을 이용합니다.

Bash 기준 최초 운영자 생성:

```bash
read -r -s -p '새 운영자 비밀번호: ' MOA_ADMIN_PASSWORD
printf '\n'
printf '%s' "$MOA_ADMIN_PASSWORD" | npm run admin -- create-admin operator
unset MOA_ADMIN_PASSWORD
```

비밀번호를 잊은 계정의 재설정:

```bash
read -r -s -p '새 비밀번호: ' MOA_ADMIN_PASSWORD
printf '\n'
printf '%s' "$MOA_ADMIN_PASSWORD" | npm run admin -- reset-password operator
unset MOA_ADMIN_PASSWORD
```

재설정은 해당 계정의 기존 세션을 종료합니다. 비밀번호를 명령 인자, GitHub 파일, 로그, 대화 메시지에 넣지 않습니다.

## 백업과 복구

실행 중인 SQLite 파일을 단순 복사하는 대신 제공한 관리 CLI로 일관된 백업을 생성합니다.

```bash
npm run admin -- backup /app/data/backups/moa-backup.sqlite
```

백업의 부모 디렉터리는 자동으로 만들어집니다. 기존 백업을 덮어쓰지 않도록 이미 있는 파일 이름은 거부하므로 날짜별로 새 파일에 저장하세요. 백업에는 참여자의 대화와 연락 정보가 포함될 수 있으므로 접근을 제한합니다. 같은 디스크에만 있는 백업은 그 디스크를 잃었을 때 함께 사라지므로 별도의 보호된 위치에도 보관합니다. 자동 외부 백업 전송은 이 앱에 구현되어 있지 않습니다.

복구는 먼저 별도의 환경에서 백업 사본으로 로그인·모임 조회를 확인한 뒤 진행합니다. 실제 복구에서는 서비스를 중지해 파일 쓰기를 막고, 기존 DB와 같은 이름의 `-wal`·`-shm` 파일을 포함한 현재 상태를 안전하게 보관합니다. 복구할 백업을 `DATABASE_PATH` 위치에 배치하고 파일 권한을 확인한 뒤 서버를 시작합니다. 백업 이후에 생긴 데이터는 그 백업에 없다는 점을 운영자가 확인해야 합니다.

호스팅의 디스크 스냅샷만으로 데이터베이스 백업을 대체하지 않습니다. 제공자의 데이터베이스 복구 주의사항과 저장소 복구 절차를 함께 확인하세요.

## 실제 이용 전에 확인할 동작

| 확인 | 기대 결과 |
| --- | --- |
| 로그인 없는 방문 | 로그인·가입 화면은 열리며 모임 대화는 볼 수 없음 |
| 초대 없는 가입 | 거절 |
| 만 13세 초대 | 운영자가 연령과 법정대리인 동의를 확인해야 발급 가능 |
| 연령대가 다른 모임 | 합류 불가 |
| 모임 탈퇴 | 사유 없이 즉시 가능하며 이전 방의 대화 접근 종료 |
| 차단과 신고 | 차단 적용, 신고를 운영자가 확인 가능 |
| 기관 연결 요청 | 동의 후 내부 대기 상태에 저장되며 외부 전송·예약 완료로 표시되지 않음 |
| 서버 재시작 | 회원·모임·메시지·연결 요청 유지 |
| 백업 복구 점검 | 별도 환경에서 저장 데이터 확인 가능 |

이 앱에는 자동 상담 인력, 24시간 모니터링 서비스, 기관 전송 연동이 포함되어 있지 않습니다. 신고와 내부 연결 요청은 실제 운영자가 확인해야 합니다. 실제 참여자를 모집할 때 운영 기관, 대응 시간, 문의 방법, 개인정보 처리와 보관 기준을 앱의 안내와 일치하도록 확정해야 합니다.
